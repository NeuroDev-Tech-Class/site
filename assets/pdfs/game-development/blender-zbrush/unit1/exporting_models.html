Exporting Models

Getting your 3D models out of Blender and into the real world

Why Export?

Blender's native file format is .blend, but most other software — game engines, 3D printers, web viewers, other 3D apps — can't read .blend files directly. To use your models elsewhere, you need to export them into a standard format that other programs understand.

How to Export

  1. Select the object(s) you want to export in Object Mode. If you want to export everything, press A to select all.
  2. Go to File > Export in the top menu bar
  3. Choose the format you want from the list
  4. In the export dialog, set your desired options (see below)
  5. Choose a file name and location, then click Export
Tip: In the export settings panel (usually on the right side of the file browser), check the "Selected Only" checkbox if you only want to export the objects you've selected — not everything in the scene. This is important when your scene contains cameras, lights, and other objects you don't want in the exported file.

Common Export Formats

Wavefront OBJ (.obj)

One of the oldest and most widely supported 3D formats. Nearly every 3D program can import OBJ files. It's a great universal choice when you're not sure what format to use.

  • Best for: Sharing between different 3D software, 3D printing
  • Supports: Geometry, basic materials (via .mtl file)
  • Limitations: No animation, no advanced materials

FBX (.fbx)

A popular format for game engines like Unity and Unreal Engine. FBX supports more data than OBJ, including animations and armatures (skeletal rigs).

  • Best for: Game engines, animation pipelines
  • Supports: Geometry, materials, animations, armatures
  • Limitations: Proprietary format (owned by Autodesk)

STL (.stl)

The standard format for 3D printing. STL files contain only geometry — no colors, no materials, no textures. If you're planning to 3D print your model, this is the format your slicer software (like Cura or PrusaSlicer) expects.

  • Best for: 3D printing
  • Supports: Geometry only
  • Limitations: No color, no materials, no animation

glTF / GLB (.gltf / .glb)

A modern, open format designed for the web and real-time applications. glTF is often called the "JPEG of 3D" because of its efficiency and wide support. GLB is the binary (single-file) version of glTF.

  • Best for: Web viewers, modern game engines, AR/VR
  • Supports: Geometry, materials (PBR), animations, textures
  • Limitations: Newer format — some older software may not support it

Export Settings to Check

When exporting, pay attention to these common settings in the options panel:

  • Selected Only — Export only selected objects (recommended)
  • Apply Modifiers — Bake modifiers into the exported mesh (usually yes)
  • Include Materials — Whether to export material data (depends on your target)
  • Scale — Some programs expect different unit scales; you may need to adjust this
  • Forward / Up Axis — Different software uses different axis conventions. Blender uses Z-up by default, while some game engines use Y-up.

Naming Conventions

Good file naming habits will save you headaches:

  • Use lowercase letters
  • Use underscores or hyphens instead of spaces (e.g., wooden_table.obj)
  • Be descriptive but concise (e.g., red_chair.fbx, not model_final_v2_FINAL_real.fbx)
  • Include version numbers if you're iterating (e.g., robot_v3.fbx)

Where to Save

Create an organized folder structure for your projects. A common approach: 

my-project/
├── blender/          ← .blend source files
├── exports/          ← exported .obj, .fbx, .stl files
├── textures/         ← image textures
└── references/       ← reference images
Always keep your .blend file! Exported formats often lose some data. Your .blend file is your primary source file — treat exports as copies for specific purposes.

Format Comparison

Format Geometry Materials Animation Best Use
OBJ Yes Basic No Universal sharing, 3D printing
FBX Yes Yes Yes Game engines
STL Yes No No 3D printing
glTF / GLB Yes Yes (PBR) Yes Web, modern apps
