Win, Lose & Checkpoints

Build the core game loop — victory conditions, failure states, and respawn points

Why These Matter

Every game needs three fundamental systems: a way to win, a way to lose, and a way to try again. Without these, you don't have a game — you just have a sandbox. In this lesson, we'll build all three as Actor Blueprints that you can drop into any level.

BP_Win — Victory Trigger

The win trigger is an invisible zone that fires when the player enters it, signaling that they've completed the level (or a major section of it).

Setting Up

  1. Create a new Actor Blueprint: right-click in the Content Browser → Blueprint Class → Actor. Name it BP_Win.
  2. Open it and add a Box Collision component. Make it the root.
  3. Scale the Box Collision to cover the victory area — large enough that the player can't accidentally skip over it (e.g., Box Extent X: 200, Y: 200, Z: 200).
  4. Set the collision's Collision Presets to OverlapAllDynamic and enable Generate Overlap Events.
  5. Optionally add a Static Mesh component for visual reference in the editor (like a flag or trophy). Set it to Hidden In Game if you want the trigger to be invisible during gameplay, or leave it visible as a goal marker.

Win Logic

  1. Select the Box Collision and add an On Component Begin Overlap event.
  2. Drag from Other Actor and add a Cast To BP_ThirdPersonCharacter — we only want the player to trigger the win, not a random physics object.
  3. From the cast's execution pin, add a Print String node: "You Win!"
  4. Optionally, after the Print String:
    • Add a Set Game Paused node (set to True) to freeze the game on victory.
    • Or create and display a Widget with a "You Win!" message and a "Play Again" button (if you've learned UMG widgets).
  5. Compile and save.
Level transition: In a multi-level game, you could replace Print String with an Open Level node to load the next level automatically. Search for "Open Level by Name" and type the level name.

BP_Checkpoint — Respawn Point

Checkpoints save the player's position so that when they die, they respawn at the last checkpoint they touched instead of starting the level over.

Setting Up the Player Variable

First, the player character needs a variable to store the checkpoint location:

  1. Open your player character Blueprint (BP_ThirdPersonCharacter).
  2. Add a Vector variable called Checkpoint.
  3. Set the default value to the Player Start's location (or 0, 0, 0 — we'll update it when the player hits a checkpoint).
  4. Compile and save the character Blueprint.

Setting Up BP_Checkpoint

  1. Create a new Actor Blueprint named BP_Checkpoint.
  2. Add a Box Collision component as the root. Size it reasonably — the player should be able to walk through it naturally (e.g., Box Extent X: 100, Y: 100, Z: 150).
  3. Set Collision Presets to OverlapAllDynamic and enable Generate Overlap Events.
  4. Optionally add a Static Mesh (like a tall thin cylinder or a flag pole) so you can see where checkpoints are in the editor.

Checkpoint Logic

  1. Add an On Component Begin Overlap event from the Box Collision.
  2. Cast to BP_ThirdPersonCharacter from the Other Actor pin.
  3. From the character output, drag and add a Set Checkpoint node (this sets the Vector variable you created on the player).
  4. For the value, use a Get Actor Location node (right-click → search "GetActorLocation"). This stores the checkpoint's position as the new respawn point.
  5. Optionally add a Print String: "Checkpoint reached!" so the player gets feedback.
  6. Compile and save.
Visual feedback: A simple Print String works, but consider changing the checkpoint mesh's material color when activated (from red to green, for example). This gives the player a clear visual cue that the checkpoint has been registered.

BP_Enemy — Failure Trigger

For now, our "enemies" are simple hazard zones — walk into them and you get sent back to the last checkpoint. We're not building AI behavior yet, just the lose/respawn mechanic.

Setting Up

  1. Create a new Actor Blueprint named BP_Enemy.
  2. Add a Static Mesh component — use a sphere or cube and give it a threatening material (red, dark, spiky-looking if you have one). This is the visible "enemy."
  3. Add a Box Collision or Sphere Collision as the root, sized slightly larger than the mesh so the player gets caught in the trigger zone.
  4. Set Collision Presets to OverlapAllDynamic and enable Generate Overlap Events.

Enemy Logic

  1. Add an On Component Begin Overlap event.
  2. Cast to BP_ThirdPersonCharacter.
  3. Add a Print String: "Game Over!"
  4. From the character output, drag and add a Get Checkpoint node to retrieve the saved checkpoint Vector.
  5. Add a Set Actor Location node (search for "SetActorLocation"). Connect the character reference to the Target pin, and the Checkpoint vector to the New Location pin.
  6. This teleports the player back to their last checkpoint instantly.
  7. Compile and save.
Test order matters: Make sure you hit a checkpoint before hitting an enemy. If the Checkpoint variable is still at its default value (0, 0, 0) and you die, you'll be teleported to the world origin — which might be underground or in the void. Always place a checkpoint near the Player Start.

Testing in a Debug Level

Before adding these actors to your main level, it's smart to test them in isolation:

  1. Create a new, simple level: File → New Level → Basic. Save it as DebugLevel.
  2. Place a flat floor mesh, a Player Start, and add one of each:
    • BP_Checkpoint — near the Player Start
    • BP_Enemy — a few meters away
    • BP_Win — at the far end of the floor
  3. Press Play and test each one:
    • Walk into the checkpoint — do you see "Checkpoint reached!"?
    • Walk into the enemy — do you see "Game Over!" and get teleported back to the checkpoint?
    • Walk into the win trigger — do you see "You Win!"?
  4. Once everything works, copy these Blueprints into your main level with confidence.
Debug levels are a professional habit. Real game studios have test levels for every mechanic. It's much faster to debug a simple flat room than a complex game level. Build the habit now.

Transferring to the Main Level

Once everything is verified in your debug level:

  1. Open your main game level.
  2. Drag BP_Checkpoint, BP_Enemy, and BP_Win from the Content Browser into the level.
  3. Position them where they make sense in your level design.
  4. Place a checkpoint near the Player Start as a safety net.
  5. Play-test the full level to make sure everything works in context.

Summary

  • BP_Win — Box Collision that prints "You Win!" (or shows a UI widget) on player overlap.
  • BP_Checkpoint — Box Collision that stores the player's location in a Checkpoint vector variable.
  • BP_Enemy — Mesh + Collision that prints "Game Over!" and teleports the player to the Checkpoint location.
  • Always test in a debug level before placing actors in your main level.
  • Place a checkpoint near the Player Start so the respawn system works from the very beginning.
