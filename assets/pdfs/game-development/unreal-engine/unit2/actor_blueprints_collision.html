Actor Blueprints & Collision

Create interactive objects with collision events and build a key-and-door system

What Are Actor Blueprints?

In the previous lesson, we worked in the Level Blueprint — logic that's tied to a specific level. Actor Blueprints (also called Blueprint Classes) are different: they represent self-contained, reusable objects. You design an Actor Blueprint once, and then you can place as many copies of it as you want in any level. Each copy runs its own independent logic.

Think of an Actor Blueprint as a template. A single BP_Coin Blueprint can spawn 50 coins across your level. A BP_Door Blueprint defines how all doors work. Change the Blueprint, and every instance updates automatically.

Creating a New Actor Blueprint

  1. In the Content Browser, navigate to (or create) a folder for your Blueprints (e.g., Content/Blueprints/).
  2. Right-click in the folder → Blueprint Class.
  3. In the class picker, choose Actor as the parent class. (Actor is the base class for anything that exists in the level.)
  4. Name it something descriptive: BP_Key, BP_Door, etc.
  5. Double-click to open it in the Blueprint Editor.

Adding Components

Actors are made of components — the pieces that give them a visible shape, collision, sound, movement, and more. You add components in the Components panel (top left of the Blueprint Editor).

Common Components

Component Purpose
Static Mesh The visible 3D shape (a sphere, cube, or imported model)
Box Collision An invisible box that detects overlaps and hits
Sphere Collision An invisible sphere that detects overlaps and hits
Point Light Emits light from a single point (torch, lamp)
Rotating Movement Automatically rotates the actor (spinning coin effect)

Component Hierarchy

Components are arranged in a parent-child hierarchy in the Components panel. When you move or rotate a parent component, all its children move with it. The topmost component is the Root — usually a collision shape or a Scene component. Attach the Static Mesh and other components as children of the root so everything stays together.

To rearrange the hierarchy, drag a component on top of another to make it a child. If you drag it to the top level, it becomes a sibling of the root.

Best practice: Use a collision component (Box or Sphere Collision) or a Scene component as the root, not the Static Mesh itself. This gives you more control over the collision bounds and prevents unexpected behavior when scaling.

Collision Events

Collision components generate events when another actor touches or enters them. The two main events are:

OnBeginOverlap

Fires when another actor enters the collision volume. The collision component must have Generate Overlap Events enabled (check the Details panel), and its Collision Presets set to something that overlaps with the player (e.g., OverlapAllDynamic).

To add this event: select the collision component in the Components panel, scroll down in the Details panel to the Events section, and click the + next to On Component Begin Overlap. This adds the event node to the Event Graph.

OnHit

Fires when another actor physically collides with the component (as opposed to passing through it). The component must have Simulation Generates Hit Events enabled. This is useful for things like jump pads, where the player needs to physically land on something.

The Cast To Node

When an overlap or hit event fires, the Other Actor output pin tells you which actor triggered the event — but it only tells you it's "an Actor." If you need to access specific variables or functions on that actor (e.g., the player's HasKey variable), you need to Cast To the specific Blueprint class.

Cast To checks: "Is this actor actually a [specific class]?" If yes (the cast succeeds), you get access to all that class's variables and functions. If no (the cast fails), nothing happens on that path.

To use it: drag from the Other Actor pin, search for Cast To ThirdPersonCharacter (or whatever your player class is named), and connect the execution pin. The As Third Person Character output pin now gives you full access to the player's Blueprint.

Why Cast To matters: Without casting, you'd have no way to check if the thing that overlapped is actually the player versus a random physics object. The cast also lets you reach into the player's Blueprint to read or change their variables — like setting HasKey to true.

Building a Key/Door System

Let's put it all together by building two Actor Blueprints: a key the player can pick up, and a door that only opens if the player has the key.

Part 1: The Key (BP_Key)

  1. Create a new Actor Blueprint and name it BP_Key.
  2. Add a Sphere Collision component as the root (or make it the root by dragging it to the top of the hierarchy). Set its Sphere Radius to about 100.
  3. Add a Static Mesh component as a child. Set its mesh to a small shape — the default Sphere or Cube works fine. Scale it down to about 0.3 so it looks like a pickup item.
  4. Optionally, change the mesh's material to something gold or bright so it stands out.
  5. Select the Sphere Collision in the Components panel. In the Details panel:
    • Set Collision Presets to OverlapAllDynamic.
    • Make sure Generate Overlap Events is checked.
  6. With the Sphere Collision still selected, scroll to the Events section and click + next to On Component Begin Overlap.
  7. In the Event Graph, you now have an OnComponentBeginOverlap event node.
  8. Drag from the Other Actor pin and add a Cast To BP_ThirdPersonCharacter node (or your player character class). Connect the execution pin.
  9. From the As BP Third Person Character output pin, drag and search for Set Has Key (we'll create this variable next). Set it to True.
  10. After the Set node, add a Destroy Actor node (search for it). This removes the key from the level once collected.
Don't forget: You need to add a Boolean variable called HasKey to your player character Blueprint (BP_ThirdPersonCharacter), not BP_Key. The key sets the player's variable to true. Default value should be false.

Part 2: The Door (BP_Door)

  1. Create a new Actor Blueprint named BP_Door.
  2. Add a Box Collision component as the root. Scale it to roughly door-sized (you can adjust the Box Extent values in the Details panel, e.g., X: 100, Y: 50, Z: 200).
  3. Add a Static Mesh component as a child. Use a Cube mesh and scale it to look like a wall or door (e.g., Scale X: 2, Y: 0.2, Z: 3).
  4. Change its material to something that suggests "locked door" — a dark color or a brick material.
  5. Set the Box Collision's Collision Presets to OverlapAllDynamic and ensure Generate Overlap Events is checked.
  6. Add the On Component Begin Overlap event (same process as the key).
  7. Add a Cast To BP_ThirdPersonCharacter from the Other Actor pin.
  8. From the cast's character output, drag and add a Get Has Key node.
  9. Add a Branch node and connect the HasKey Boolean to the Condition pin.
  10. True path: Add a Destroy Actor node — the door disappears, letting the player through.
  11. False path: Add a Print String node with the text "Locked — find the key!"

Testing the System

  1. Compile and save both Blueprints.
  2. Go to your level and drag a BP_Key and a BP_Door into the viewport.
  3. Press Play. Walk into the door first — you should see "Locked — find the key!" Walk into the key (it should disappear). Then walk into the door again — it should disappear, letting you through.
  4. If something doesn't work, add Print String nodes at each step of the logic to trace where the issue is.

Summary

  • Actor Blueprints are reusable, self-contained objects made of components.
  • Components provide visuals (Static Mesh), collision detection (Box/Sphere Collision), and more.
  • OnBeginOverlap fires when something enters a collision volume; OnHit fires on physical contact.
  • Cast To verifies an actor's class and gives access to its variables and functions.
  • A key/door system combines overlap events, casting, Booleans, and Branches into a complete gameplay mechanic.
