Intro to Unreal Engine

Introduction to Blueprints

Learn Unreal Engine's visual scripting system — no coding required

What Are Blueprints?

Blueprints are Unreal Engine's visual scripting system. Instead of writing lines of code in a text file, you create logic by placing nodes on a graph and connecting them with wires. Each node represents an action, a piece of data, or a decision — and the wires tell the engine what order to do things in and what information to pass along.

Professional game studios use Blueprints alongside traditional C++ code, but you can build entire games using only Blueprints. They're powerful enough for real production work, and they're the perfect starting point for learning game logic.

Think of it this way: If Unreal Engine is a kitchen, Blueprints are your recipe cards. Each card (node) tells the engine to do one thing — "play a sound," "move the player," "check if a door is locked." You connect the cards in order to create complete gameplay systems.

The Blueprint Editor

When you open a Blueprint, you'll see the Blueprint Editor — a dedicated workspace with several panels. The most important one is the Event Graph.

The Event Graph

The Event Graph is the large grid area where you build your logic. This is where you place nodes, connect wires, and create the behavior for your game. Think of it as your canvas — you can pan around by holding the right mouse button and dragging, and zoom in/out with the scroll wheel.

Nodes

Nodes are the building blocks of Blueprints. Each node is a rectangular box that does one specific thing. Some common examples:

  • Event nodes — trigger when something happens (e.g., the game starts, a key is pressed)
  • Action nodes — do something (e.g., print text, play a sound, move an object)
  • Data nodes — hold or calculate values (e.g., a number, a true/false value)

Wires

Wires connect nodes together. You create a wire by clicking on a pin on one node and dragging it to a pin on another node. There are two types of pins:

  • Execution pins (white arrows) — control the order things happen. They look like white triangles on the left and right sides of a node. The flow goes left to right: when a node finishes, it fires its output execution pin, which triggers the next node.
  • Data pins (colored circles) — pass information between nodes. Different colors represent different data types: green for Booleans (true/false), teal for integers (whole numbers), light green for floats (decimals), magenta for strings (text), and yellow for vectors (X, Y, Z positions).
Key difference: Execution pins control when something happens. Data pins control what information is used. You'll use both on almost every node.

Level Blueprint vs. Actor Blueprints

There are two main places you can write Blueprint logic:

  • Level Blueprint — belongs to the current level (map). Logic here affects the entire level. Good for things like "when the level starts, play a cutscene" or "when the player enters this area, open a door." Every level has exactly one Level Blueprint.
  • Actor Blueprints (Blueprint Classes) — belong to a specific object (actor) that you can place in any level. Good for reusable things like coins, enemies, doors, or weapons. You can place multiple copies of the same Actor Blueprint in a level, and each one runs its own logic independently.

We'll start with the Level Blueprint since it's the simplest way to get your first logic running. In later lessons, we'll move to Actor Blueprints for more powerful, reusable systems.

Opening the Level Blueprint

  1. Open any level in Unreal Engine.
  2. In the toolbar at the top, click the Blueprints dropdown button (it has a blue hexagon icon).
  3. Select Open Level Blueprint.
  4. The Blueprint Editor will open, showing the Event Graph for this level.

Creating Your First Nodes

Let's create a simple Blueprint that prints a message when the game starts.

Adding Nodes

  1. Right-click anywhere on the Event Graph grid. A search menu appears — this is how you add every node in Blueprints.
  2. Type BeginPlay in the search bar and select Event BeginPlay. This node fires once when the game starts (when you press Play).
  3. Right-click on an empty area again and search for Print String. Select it.
  4. You now have two nodes on your graph. Connect the output execution pin (white arrow) on BeginPlay to the input execution pin on Print String by clicking and dragging from one to the other.
  5. In the Print String node, you'll see a text field labeled In String. Type a message like Hello, Unreal!.
  6. Click Compile (the big blue checkmark button at the top left of the Blueprint Editor), then close the Blueprint Editor.
  7. Press Play (Alt+P) — your message should appear in the top-left corner of the viewport!
Always Compile! After making changes to any Blueprint, click the Compile button. This tells Unreal to process your changes. If there's an error, the Compile button will show a red X and tell you what went wrong.

The BeginPlay Event

Event BeginPlay is one of the most important event nodes. It fires exactly once — the moment the game starts running (or when the actor is first created in the world). Use it for setup tasks: initializing variables, creating UI widgets, printing debug info, or starting background logic.

The Print String Node

Print String displays text on-screen during gameplay. It's Unreal's version of print() or console.log(). It's your best friend for debugging — whenever you want to check if something is working, add a Print String to see if that part of your Blueprint is being reached. You can change the text color and duration in the node's details.

Comment Boxes for Organization

As your Blueprint grows, it will get messy fast. Comment boxes help you stay organized by grouping related nodes together with a label.

  1. Select one or more nodes (click and drag a selection box around them, or Ctrl+click individual nodes).
  2. Press C on your keyboard.
  3. A comment box appears around the selected nodes. Type a descriptive title like Setup, Gold System, or Door Logic.
  4. You can change the comment color by right-clicking the comment header bar and choosing Comment Color.
Get in the habit now: Always comment your Blueprint sections. Professional developers comment constantly. When you come back to a Blueprint a week later, you won't remember what each cluster of nodes does — but a comment box labeled "Check if player has key" will tell you instantly.

Summary

  • Blueprints are a visual scripting system — logic without code.
  • The Event Graph is where you place nodes and connect them with wires.
  • Execution pins (white arrows) control order; data pins (colored circles) pass information.
  • The Level Blueprint controls the current level; Actor Blueprints control individual objects.
  • BeginPlay fires when the game starts; Print String displays debug text.
  • Use comment boxes (C) to keep your graphs organized.
