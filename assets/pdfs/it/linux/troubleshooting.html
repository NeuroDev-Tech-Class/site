Basic Troubleshooting Techniques

How to diagnose and fix common Linux problems

The Troubleshooting Mindset

Things will break. That's not a failure — it's a learning opportunity. The best Linux users aren't the ones who never have problems; they're the ones who know how to figure out what went wrong and fix it.

Here's a simple framework you can use every time something goes wrong:

  1. Read the error message — Seriously, read the whole thing. It usually tells you what's wrong.
  2. Reproduce the problem — Can you make it happen again? What exact steps trigger it?
  3. Research — Copy/paste the error message into a search engine. Someone has probably seen it before.
  4. Isolate — Change one thing at a time to narrow down the cause.
  5. Fix and verify — Apply a fix, then confirm the problem is actually gone.

Common Problem: "Command Not Found"

$ htop
Command 'htop' not found, but can be installed with:
sudo apt install htop

What this means: The program isn't installed on your system.

How to fix it:

# Install the missing program
sudo apt install htop

# If you're not sure of the package name, search for it
apt search htop

Common Problem: "Permission Denied"

$ ./script.sh
bash: ./script.sh: Permission denied

What this means: You don't have permission to execute this file.

How to fix it:

# Check current permissions
ls -l script.sh

# Add execute permission
chmod +x script.sh

# If it's a system file, you might need sudo
sudo chmod +x script.sh

Common Problem: "No Space Left on Device"

$ cp bigfile.zip /home/alice/
cp: error writing '/home/alice/bigfile.zip': No space left on device

What this means: Your disk is full.

How to fix it:

# Check disk usage
df -h

# Find large files and directories
du -sh /* 2>/dev/null | sort -rh | head -10

# Clean up package manager cache
sudo apt clean

# Remove old packages no longer needed
sudo apt autoremove

Common Problem: "Unable to Locate Package"

$ sudo apt install coolprogram
E: Unable to locate package coolprogram

What this means: The package doesn't exist in your current repositories, or your package list is outdated.

How to fix it:

# Update your package list first
sudo apt update

# Try again
sudo apt install coolprogram

# If still not found, check the spelling or search
apt search cool

Common Problem: A Program is Frozen

What this means: A process has stopped responding.

How to fix it:

# If your terminal is stuck, try Ctrl+C to cancel the current command
# Press Ctrl+C

# If a background program is frozen, find it and kill it
ps aux | grep frozen-program
kill [PID]

# If it won't die, force kill it
kill -9 [PID]

# Or use htop to find and kill it interactively
htop

Common Problem: "Could Not Get Lock"

E: Could not get lock /var/lib/dpkg/lock-frontend
E: Unable to acquire the dpkg frontend lock

What this means: Another program is currently using the package manager (like an automatic update running in the background).

How to fix it:

# Wait a minute and try again — it's probably an auto-update

# Check if another apt process is running
ps aux | grep apt

# If it's stuck, you can (carefully!) remove the lock
sudo rm /var/lib/dpkg/lock-frontend
sudo rm /var/lib/apt/lists/lock
sudo dpkg --configure -a
Only remove lock files as a last resort! Usually, you just need to wait for the other process to finish. Removing locks while another process is actively using them can cause problems.

Reading Log Files

Linux keeps detailed logs of system events. These are your best friend when troubleshooting:

# View the system log (recent entries)
journalctl -xe

# View only error messages
journalctl -p err

# Follow the log in real-time (like a live feed)
journalctl -f

# Check the traditional syslog
cat /var/log/syslog | tail -50

# Check authentication/login logs
cat /var/log/auth.log | tail -20

The Power of Search Engines

When you encounter an error you don't recognize:

  1. Copy the exact error message (excluding file paths specific to your system)
  2. Add "Ubuntu" or "Linux" to your search query
  3. Check these resources:
    • Ask Ubuntu (askubuntu.com) — Q&A site specifically for Ubuntu
    • Stack Overflow — Programming and sysadmin Q&A
    • Arch Wiki (wiki.archlinux.org) — Incredibly detailed Linux documentation (works for Ubuntu too)
    • Man pages — Type man [command] for built-in documentation
Don't forget man pages! Almost every command has built-in documentation. Try man ls, man chmod, or man apt. Press q to quit. You can also use [command] --help for a shorter summary.

Troubleshooting Checklist

When something goes wrong, run through this checklist:

  1. Did you read the entire error message?
  2. Did you check your spelling? (Linux is case-sensitive!)
  3. Are you in the right directory? (pwd)
  4. Do you have the right permissions? (ls -l)
  5. Do you need sudo?
  6. Is the program installed? (which [program])
  7. Is your package list up to date? (sudo apt update)
  8. Is there enough disk space? (df -h)
  9. Is the service running? (systemctl status [service])
  10. What do the logs say? (journalctl -xe)

Try It Yourself

  1. Run uname -a and cat /etc/os-release to check your system info.
  2. Try running a program that doesn't exist: fakecommand123. Read the error message carefully.
  3. Check your disk space with df -h.
  4. Read the man page for a command you've used: man ls. Use q to quit.
  5. Check recent system logs with journalctl -xe (use arrow keys to scroll, q to quit).
  6. Test your internet connection with ping -c 4 google.com (sends 4 pings then stops).
