Introduction to Linux

I Broke It — Now What?

A survival guide for when things go wrong in Linux

First: Don't Panic

Breaking things is a normal part of learning Linux. Every experienced Linux user has accidentally deleted important files, corrupted a config, or locked themselves out of their system at some point. The good news? Most things are fixable, and every mistake teaches you something valuable.

Golden Rule: If you don't know what a command does, don't run it with sudo. Research it first!

Scenario 1: "I Deleted Something Important"

The Problem

You ran rm on a file you actually needed.

What to Do

  • Stop immediately. The more you use the system, the harder recovery becomes.
  • Unlike Windows, Linux doesn't have a Recycle Bin in the terminal. Files removed with rm are gone.
  • If using a GUI file manager, check the Trash folder first.
  • For WSL users: if the file was in your Windows filesystem (/mnt/c/), check the Windows Recycle Bin.

How to Prevent It

# Use -i (interactive) flag — asks before each deletion
rm -i important_file.txt

# Use -I (capital i) for bulk deletions — asks once for confirmation
rm -I *.txt

# Never use rm -rf / or rm -rf * without double-checking your location
pwd  # Always check where you are first!
The Scariest Linux Command: sudo rm -rf / would attempt to delete your entire filesystem. Never run this! Modern Linux systems have safeguards against it, but variations of this command can still cause serious damage.

Scenario 2: "I Edited a Config File and Now Things Are Broken"

The Problem

You changed a system configuration file (like /etc/fstab, /etc/hosts, or ~/.bashrc) and now something doesn't work.

What to Do

# If you made a backup first (good practice!), restore it:
sudo cp /etc/hosts.bak /etc/hosts

# If you messed up .bashrc and your terminal is acting weird:
# Open the file and fix it, or reset to default:
cp /etc/skel/.bashrc ~/.bashrc
source ~/.bashrc

# If you can't even open a terminal, try:
# 1. Press Ctrl+Alt+F2 to get a text-only console
# 2. Log in
# 3. Fix the broken file

How to Prevent It

# ALWAYS make a backup before editing system files!
sudo cp /etc/hosts /etc/hosts.bak

# Then edit the file
sudo nano /etc/hosts

Scenario 3: "I Can't Install Anything"

The Problem

Running sudo apt install gives errors.

What to Do

# Step 1: Update your package list
sudo apt update

# Step 2: Fix broken packages
sudo apt --fix-broken install

# Step 3: Clean and retry
sudo apt clean
sudo apt update
sudo apt install [package-name]

# Step 4: If there's a lock file error, check for running processes
ps aux | grep apt
# Wait for them to finish, or if they're stuck, remove the lock:
sudo rm /var/lib/dpkg/lock-frontend
sudo dpkg --configure -a

Scenario 4: "My Terminal Is Acting Strange"

The Problem

Your terminal looks weird — garbled text, no color, or commands aren't working right.

What to Do

# Reset the terminal display
reset

# If that doesn't help, try:
stty sane

# If your shell prompt looks wrong, reload your shell config:
source ~/.bashrc

# If nothing works, close and reopen your terminal

Scenario 5: "I Forgot My Password"

The Problem

You can't remember your Linux password.

What to Do

For WSL users:

# Open PowerShell (not WSL) and run:
wsl -u root

# Now you're root — reset your password:
passwd your_username

# Type the new password (nothing will appear — that's normal)
# Exit and restart WSL
exit

For VM or desktop users:

  • Reboot the system
  • Hold Shift during boot to access the GRUB menu
  • Select "Advanced options" → "Recovery mode"
  • Choose "root — Drop to root shell prompt"
  • Run passwd your_username
  • Reboot normally

Scenario 6: "The System Won't Boot" (VM Only)

The Problem

Your virtual machine won't start or gets stuck.

What to Do

  • Try restarting the VM — Power off and start fresh
  • Boot into recovery mode — Hold Shift at boot, select recovery options
  • Check VM settings — Make sure RAM and CPU allocation are reasonable
  • Take snapshots before experiments — You can restore to a known-good state
VirtualBox Snapshots are your best friend! Before making any major changes, take a snapshot of your VM. You can always restore it if things go wrong. Go to Machine → Take Snapshot in VirtualBox.

Best Practices to Avoid Disasters

Before You Act

  • Always back up config files before editing them (cp file file.bak)
  • Use VM snapshots before major changes
  • Read error messages completely — they usually tell you what's wrong
  • Use pwd before destructive commands to confirm your location
  • Use ls before rm to verify what you're about to delete
  • Don't blindly copy-paste commands from the internet — understand what they do first

Good Habits

  • Run sudo apt update && sudo apt upgrade regularly to keep your system current
  • Use history to review recent commands if you need to trace what you did
  • Keep notes on changes you make to the system
  • Learn to use man pages and --help flags
  • Experiment in a VM or WSL — it's a safe sandbox for learning

Key Takeaway

Breaking things is part of the process. The goal isn't to avoid mistakes — it's to develop the skills to fix them and the habits to minimize damage. Every error you troubleshoot makes you a more capable Linux user.
