File Permissions and Ownership

Controlling who can read, write, and execute files in Linux

Why Permissions Matter

Linux is a multi-user operating system. That means multiple people (or programs) can be logged into the same machine at the same time. File permissions are the system that decides who can do what with each file and directory. Without them, any user could read, modify, or delete anyone else's files — that would be chaos!

Viewing Permissions

You can see file permissions by running ls -l (the "long listing" option):

$ ls -l
-rw-r--r-- 1 alice students  4096 Mar 15 10:30 report.txt
drwxr-xr-x 2 alice students  4096 Mar 15 10:31 Projects
-rwxr-x--- 1 alice students   512 Mar 15 10:32 script.sh

Let's break down the first line:

-rw-r--r-- 1 alice students 4096 Mar 15 10:30 report.txt
│├──┤├──┤├──┤   │      │
│  │   │   │    │      └── Group owner
│  │   │   │    └── User owner
│  │   │   └── Others permissions (r--)
│  │   └── Group permissions (r--)
│  └── User permissions (rw-)
└── File type (- = regular file, d = directory)

The Three Permission Types

Permission Symbol For Files For Directories
Read r View the file's contents List the directory's contents (ls)
Write w Modify or overwrite the file Add or delete files in the directory
Execute x Run the file as a program/script Enter the directory with cd

A dash (-) in place of a letter means that permission is not granted.

The Three User Categories

Permissions are applied to three categories of users:

  1. User (u) — The owner of the file. Usually the person who created it.
  2. Group (g) — A set of users who share certain access rights. Every file belongs to one group.
  3. Others (o) — Everyone else on the system who isn't the owner and isn't in the group.

Reading the Permission String

The 9-character permission string is divided into three sets of three:

rw-  r--  r--
│    │    │
│    │    └── Others: read only
│    └── Group: read only
└── User: read and write

Changing Permissions with chmod

The chmod (change mode) command lets you change file permissions. There are two ways to use it: symbolic mode and numeric mode.

Symbolic Mode

In symbolic mode, you specify who, what action, and which permission:

# Give the user (owner) execute permission
chmod u+x script.sh

# Remove write permission from group and others
chmod go-w report.txt

# Give everyone read permission
chmod a+r readme.txt

# Set exact permissions: user=rwx, group=rx, others=nothing
chmod u=rwx,g=rx,o= script.sh
Symbol Meaning
uUser (owner)
gGroup
oOthers
aAll (user + group + others)
+Add permission
-Remove permission
=Set exact permission

Numeric (Octal) Mode

In numeric mode, each permission has a number value:

  • Read (r) = 4
  • Write (w) = 2
  • Execute (x) = 1
  • No permission = 0

You add the values together for each user category to create a three-digit code:

Permissions Calculation Value
rwx4 + 2 + 17
rw-4 + 2 + 06
r-x4 + 0 + 15
r--4 + 0 + 04
---0 + 0 + 00
 
# rwx for user, r-x for group, r-- for others
chmod 754 script.sh

# rw- for user, r-- for group and others
chmod 644 report.txt

# rwx for user, nothing for group and others
chmod 700 private_script.sh
Common Permission Sets:
  • 755 — Standard for executable scripts and directories (owner can do everything, others can read and execute)
  • 644 — Standard for regular files (owner can read/write, others can only read)
  • 700 — Private (only the owner can access)

File Ownership

Every file has two owners:

  • User owner — Usually the person who created the file
  • Group owner — The group associated with the file

Changing Ownership with chown

The chown (change owner) command changes who owns a file. You typically need sudo to use it:

# Change the user owner to bob
sudo chown bob report.txt

# Change both user and group owner
sudo chown bob:teachers report.txt

# Change only the group owner
sudo chown :teachers report.txt

# Change ownership of a directory and everything inside it (-R = recursive)
sudo chown -R bob:teachers Projects/

Changing Group with chgrp

The chgrp command changes just the group owner:

sudo chgrp teachers report.txt

The Superuser: sudo

Some actions require root (administrator) privileges. The sudo command lets authorized users run commands as root:

# Install software (requires root)
sudo apt install htop

# Edit a system configuration file
sudo nano /etc/hostname
Be careful with sudo! Running commands as root bypasses all permission checks. A typo in a sudo rm command could delete critical system files. Always double-check your commands before pressing Enter.

Real-World Example

Let's say you write a bash script and want to make it runnable:

# Create a simple script
echo '#!/bin/bash' > greet.sh
echo 'echo "Hello, $(whoami)!"' >> greet.sh

# Check its permissions
ls -l greet.sh
# -rw-r--r-- 1 alice students 45 Mar 15 greet.sh

# Try to run it — Permission denied!
./greet.sh
# bash: ./greet.sh: Permission denied

# Add execute permission
chmod u+x greet.sh

# Check permissions again
ls -l greet.sh
# -rwxr--r-- 1 alice students 45 Mar 15 greet.sh

# Now it works!
./greet.sh
# Hello, alice!

Try It Yourself

  1. Create a file with touch secret.txt and check its default permissions with ls -l.
  2. Remove all permissions for group and others: chmod go-rwx secret.txt
  3. Verify with ls -l — it should show -rw-------.
  4. Create a script file: echo '#!/bin/bash' > test.sh && echo 'echo "It works!"' >> test.sh
  5. Try running it with ./test.sh — it should fail.
  6. Add execute permission: chmod +x test.sh
  7. Run it again — it should work now!

Key Takeaways

  • Permissions control who (user, group, others) can do what (read, write, execute).
  • Use ls -l to view permissions and chmod to change them.
  • Numeric mode (like 755) is fast; symbolic mode (like u+x) is more readable.
  • Use chown to change file ownership and chgrp to change the group.
  • Use sudo carefully — it gives you full root power.
